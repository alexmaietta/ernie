Batched cameras

One camera rendering a view per environment for reinforcement learning (ernie.batch).

Batched cameras for reinforcement learning: one camera renders a view per environment, each from its own pose of its own world, and every step hands back the observations as GPU arrays.

import ernie
from ernie.batch import BatchCamera

renderer = ernie.Renderer()
scene = ...  # environments cloned under Xforms with world=0, 1, ... (see Scene.clone)
camera = BatchCamera(renderer, scene, "/World/Camera", views=4096, resolution=(64, 64),
                     render_vars=("LdrColor", "DistanceToCamera"))
camera.set_worlds(numpy.arange(4096, dtype=numpy.int32))
for step in range(steps):
    poses = simulator.camera_poses()            # (4096, 4, 4) float32, e.g. a CUDA tensor
    observations = camera.step(poses, stream=torch.cuda.current_stream().cuda_stream)
    rgb = torch.from_dlpack(observations["LdrColor"])[..., :3]  # (4096, 64, 64, 3) uint8

Nothing waits on the host: poses written as a contiguous float32 CUDA array stay on the GPU (tokens.POSES_DEVICE), the render is submitted and the next step is prepared while it runs, and the observations are ready for work queued on stream after the call. Each step's arrays belong to that step's frame: keep them as long as needed, but drop them before many more steps, or each step renders into a frame of its own.

Observation shapes: LdrColor (views, rows, cols, 4) uint8 sRGB; HdrColor, Electrons and Normal (views, rows, cols, 4) float32; DistanceToCamera and DistanceToImagePlane (views, rows, cols) float32; PrimId and InstanceId (views, rows, cols) uint32; RawDN (views, rows, cols, 4) uint16; SpectralRadiance (views, bands, rows, cols) float32. Only the vars asked for are rendered and held.

References: - B. Shacklett et al., "An Extensible, Data-Oriented Architecture for High-Performance, Many-World Simulation", SIGGRAPH 2023 (Madrona's batch renderer). https://madrona-engine.github.io/ - M. Mittal et al., "Orbit: A Unified Simulation Framework for Interactive Robot Learning Environments", IEEE RA-L 2023 (Isaac Lab's tiled cameras). https://isaac-sim.github.io/IsaacLab/

A batch of views views through the Camera prim camera of scene, rendered by renderer as the render product product at resolution (columns, rows) with render_vars.

The camera keeps its lens and sensor; each view replaces its transform with a pose under the camera's parent (tokens.POSES) and sees one world (tokens.WORLDS) besides what every world shares, or every world for -1. A missing camera is defined with default settings. Until the first poses, every view takes the camera's own transform, and views see every world.

minimal draws the product with minimal shading (tokens.MINIMAL_MODE) for throughput: "none" (black, for distances, normals and ids alone), "constantDiffuse" (minimal_color lit by the sun and ambient) or "texturedDiffuse" (surfaces' diffuse colours so lit), in one forward pass straight into the observations, which then map to CUDA without a copy.

map_poses 

map_poses(stream: Any = None) -> Any

The views' poses as a writable CUDA array over the renderer's own memory, holding the poses as they are: write the next step's poses into it on stream and call step() without poses, and nothing is copied. Map again each step. Needs poses written on the GPU first (a contiguous float32 CUDA array, as set_poses takes).

set_poses 

set_poses(poses: Any, stream: Any = None) -> None

Sets every view's camera-to-world pose under the camera's parent: a (views, 4, 4) array in the math convention (translation in the last column) from any DLPack framework. Contiguous float32 CUDA arrays stay on the GPU, copied after the work queued on stream.

set_worlds 

set_worlds(worlds: Any, stream: Any = None) -> None

Sets the world each view sees (tokens.WORLD of the environments' prims): a (views,) int32 array, -1 for every world. A CUDA array is copied to the host once per write, after the work queued on stream, for planning the views' shadows.

step 

step(
    poses: Any = None, worlds: Any = None, *, stream: Any = None, device: str = "cuda"
) -> Mapping[str, Any]

Renders a step, after setting poses and worlds when given, and returns each render var's observations by name.

With device="cuda", the arrays are in GPU memory (DLPack, e.g. torch.from_dlpack) and the call returns once the step is submitted: work queued on CUDA stream stream (a CUstream handle or DLPack stream number, default the legacy stream) after it sees the finished render. With device="cpu", it waits for the render and returns NumPy arrays.

Detailed Description

The scene is the single source of truth. A delegate pulls its changes on Sync (each delegate keeps its own ChangeCursor) and uploads only what changed, so there is no separate render index. Every backend reads the scene with the same resolution rules (resolve.h) and writes the same render vars through the camera's sensor filters (sensor_filters.h).

There are two ways to render: * headless and in simulation: StepAsync (or Step and Render) renders the UsdRender products of a scene and returns their render vars; * interactively: Update then Record into the application's own command buffer each frame, submitted after SubmitWaits.

Rendering is deterministic: an image's noise and samples derive from the camera's ernie:sensor:seed, its render product's path and its frame number (NextFrame), so the same scene renders the same images on any machine and whatever else renders alongside.

function StepAsync

Renders products ofscene (seeResolveRenderProducts ) and returns at once: wait for or poll the operation, then fetch the outputs and map their render vars.

virtual StepOperation ernie::RenderDelegate::StepAsync (
    const Scene & scene,
    std::span< const Path > products={},
    const Path & settings={},
    double deltaTime=0.0
) = 0

A product through several cameras or a camera with ernie:poses renders a batch of views (ViewPosesOf), such as one per environment in reinforcement learning, in one submission; its render vars gain a leading view dimension. Each product renders into a frame of its own that later steps reuse once its outputs are dropped and unmapped. Steps do not wait for earlier ones to finish: the next step is prepared while the last renders, so a loop that maps its outputs to CUDA without waiting keeps the GPU busy (a backend may bound the steps in flight, as the rasterizer does at two).

The step first moves the sensor clock on by deltaTime seconds (AdvanceTime; none by default), so its frames span the clock from the last frame's end to the new time, as ovrtx's step simulates [last time, last time + delta].

Exception:

  • std::invalid_argument as ResolveRenderProducts, Update and AdvanceTime.

function Time

The sensor clock, seconds: where the last frame ended. 

inline double ernie::RenderDelegate::Time () const

Steps advance it by their deltaTime (StepAsync), an interactive view by AdvanceTime before each Update, and ResetTime sets it, as ovrtx's step and reset do. Each frame spans the clock from the last frame's end to now (FrameParams::startTime, time): what its lights, pulses and rolling shutter run through. The scene's animation has a clock of its own (Stage::GetTimeCode), so it can hold or loop while sensors run on.

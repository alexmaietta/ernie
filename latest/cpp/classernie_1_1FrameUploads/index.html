Class ernie::FrameUploads

ClassList > ernie > FrameUploads

Host data bound for device buffers, staged for one frame in flight and copied by that frame's own commands ( Record ), so the host can prepare a frame while the device still runs earlier ones that read the same buffers: the copies wait on the device for that earlier work, in queue order, rather than the host waiting for it.More...

Detailed Description

Writes keep their order, so a buffer written in part, or twice, ends as if written in place.

Each of kSlots slots has its own staging memory. A frame takes a slot with Begin once the frame that last used that slot has finished; writes until its Record stage there.

References: * Khronos, "Synchronization Examples", transfer then use in a later submission. https://github.com/KhronosGroup/Vulkan-Docs/wiki/Synchronization-Examples * A. Kapoulkine, "niagara", per-frame staging of uploads. https://github.com/zeux/niagara

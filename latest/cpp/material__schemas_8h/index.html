Namespaces

Type Name
namespace ernie
Prim types as reflected schemas: each type declares its attributes once, as a list of (C++ type, name, USD token, fallback, metadata) entries, and that list gives both a typed view class overScene (GetRadius ,HasRadius ,SetRadius ) and the type's entry in a runtime registry (PrimTypeDef ), which generic code walks: Python's typed prim classes, the viewer's property panels, loaders.

Materials as reflected schemas ( prim_type.h ): UsdShade's Material, with Ernie's own surface inputs (a BRDF model, an albedo, an albedo map and detail textures), and Shader, the nodes of a UsdShade network (UsdPreviewSurface, UsdUVTexture, UsdPrimvarReader_float2, UsdTransform2d) byinfo:id .

    X
)

Each declaration's fallback is the value Ernie shades an unset input with (MaterialSettings, DetailSettings, TextureReader, the preview_surface model's defaults).

Not declared, and read generically: a BRDF's own parameters (inputs:<param> per model in the BrdfRegistry, an open namespace), connections (<input>.connect, through GetConnection), and inputs:scale, which is UsdUVTexture's 4-vector scale and UsdTransform2d's 2-vector one under one name on the one Shader type: a declaration of either type would author the other Shader's scale as the wrong USD type.

References: * Pixar, UsdShade, https://openusd.org/release/api/usd_shade_page_front.html * Pixar, "UsdPreviewSurface Specification", https://openusd.org/release/spec_usdpreviewsurface.html

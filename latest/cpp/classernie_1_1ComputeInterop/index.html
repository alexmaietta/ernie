Class ernie::ComputeInterop

ClassList > ernie > ComputeInterop

Zero-copy sharing between a Vulkan device and the compute device behind it (CUDA or HIP), so arrays from compute frameworks (PyTorch, JAX, CuPy, Warp, simulators) reach Ernie's buffers, and Ernie's results reach them, without passing through host memory. More...

Detailed Description

Vulkan memory is exported as POSIX file descriptors (BufferMemory::Shared) and imported into the compute API as external memory; the compute driver is loaded at run time, so Ernie has no build dependency on any GPU toolkit. The two sides order their work on the GPU, without blocking the host, through two timeline semaphores created in Vulkan and imported into the compute API, one per direction so each side signals only its own: * compute to Vulkan: CopyToBuffer queues its copy and signals the next value; Vulkan submissions that read the buffer wait for VulkanWait. * Vulkan to compute: a Vulkan submission whose writes the compute side reads signals NextVulkanSignal; compute streams wait for it with WaitForVulkan, and Download waits for it itself.

Streams are numbered as in DLPack for the backend's device kind (for CUDA: 1 the legacy default stream, 2 the per-thread default stream, anything else a stream handle).

Reference: Khronos, VK_KHR_external_memory_fd, https://registry.khronos.org/vulkan/specs/latest/man/html/VK_KHR_external_memory_fd.html
